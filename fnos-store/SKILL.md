# 飞牛磁盘与存储

用已验证的专用 CLI 查询和管理 fnOS 存储。先建立“设备 → 磁盘 → 存储空间/卷”的对应关系，分别评估物理磁盘健康与存储空间状态，不能用其中一项正常代替另一项检查。

## 入口与认证

**前置技能：using-fnos。** 直接命中本技能时，先读取相邻的 `../using-fnos/SKILL.md`，按其工具选择、设备绑定、版本探测和兼容登录流程完成连接；已有验证结果可复用。由 using-fnos 路由而来时不重新登录，也不再次路由。

认证流程只有 using-fnos 一处维护，不在这里另创登录方式。非 fnOS 设备按真实系统选择工具，不执行以下 fnOS 命令。

**没有目标 server/profile、会话过期或需要用户登录，都属于连接认证待完成，不是 CLI 缺少存储能力的证据。** 继续兼容登录流程，不因 SSH 可用或浏览器已登录而跳过 CLI。需要用户操作时给出具体步骤，等待期间只做不依赖认证的工作，不索取密码或 token。

## 查询顺序

先看所选客户端当前版本的存储帮助，再发业务请求。`Timandes/fnos-cli` 的包名是 `fnos-cli`，入口是 `fnos`；下表为本机 0.6.0 已核实的命令，其他客户端按自身帮助执行。每次业务调用显式指定目标 server/profile。

| 目的 | fnos 命令与参数 |
| --- | --- |
| 存储空间、卷及容量概况 | `store general` |
| 物理磁盘、型号、序列号及归属 | `store listDisk` |
| 每块盘的现有 SMART 信息 | `store diskSmart --disk <实际设备名>` |
| 阵列/存储状态 | `store state --name <实际阵列名>` 或 `--uuid <实际UUID>` |
| 磁盘 I/O | `resmon disk` |
| 缓存/休眠等专项信息 | `store --help` 中实际存在的对应只读命令 |

例如：已按 using-fnos 验证 `nas-9` 后，先确认帮助，再查询：

```sh
fnos store --help
fnos store diskSmart --help
fnos --raw store general --server nas-9
fnos --raw store listDisk --server nas-9
# 仅当列表确实包含 sda 时执行；其余磁盘逐一使用列表中的实际名称。
fnos --raw store diskSmart --disk sda --server nas-9
```

从响应提取真实阵列名/UUID 后查询 state，不猜名称或参数。按问题范围读取，普通磁盘健康分析覆盖全部相关物理盘；只问容量时不必额外读取所有 SMART。读写性能监控按 using-fnos 的采样和单位规则执行。

## 能力缺口与回退

只有以下证据才支持回退：当前帮助及同版本文档确认缺所需接口/认证方式，或真实请求返回经核实的系统不支持/接口缺失。先确认不是参数用错、网络故障、会话失效、scope 或账户权限问题。

回退前向用户简述“缺哪个指标或操作、哪项证据、改用什么工具”。按 using-fnos 选择兼容客户端、API、SSH 或已有管理页。CLI 能取得的部分先用 CLI 完成，其他工具只补缺口。用户明确指定工具时遵循用户要求。

| 容易误判的理由 | 应做的事 |
| --- | --- |
| 没有 nas-9 的会话，SSH 已能登录 | 按 using-fnos 完成目标 CLI 登录 |
| 帮助已经看过，可以直接去管理页 | 帮助只证明入口存在，接着发目标只读请求 |
| CLI 未给 NVMe 错误码或 Btrfs 统计 | 明确缺口后用其他工具补取，不重新用 UI 采集全部指标 |

## 磁盘：先分类，再判断健康

先根据实际型号、厂商规格、介质类型和接口/协议确定每块盘的类型，再选择健康指标。报告型号、序列号、类型和所属存储空间。常见类型包括 U.2 SSD、NVMe SSD、SATA SSD、SAS HDD、SATA HDD；其他类型按实际结果标注。

- U.2 是外形/连接规格，NVMe 是协议，二者可同时成立；型号资料确认后可标为“U.2 NVMe SSD”。只有 NVMe 协议不能推断为 M.2 或 U.2，也不能仅凭 `sdX`/`nvmeXnY` 设备名判断介质与外形。
- 接口字段与型号资料不一致时核对转接器/桥接影响；不能确认的类型明确标为未知，并说明缺少什么证据。

| 磁盘类型 | 必查健康指标与判断 |
| --- | --- |
| 普通 HDD（如 SATA HDD） | 重点检查 SMART **05 / Reallocated_Sector_Ct** 原始值；非零时标为关注项，结合历史判断是否增长，同时查看待映射、不可纠正等错误。SMART 总体通过不能掩盖 05 非零。 |
| SAS HDD | 重点检查 **G 表 / grown defect list**（运行中新增缺陷表）条目数；非零时标为关注项，结合历史判断是否增长。不能用 P 表/出厂缺陷数量替代 G 表，也不能将缺少 ATA SMART 05 当作无坏块。 |
| SSD（含 U.2、NVMe、SATA、SAS SSD） | 重点检查健康度/寿命：厂商定义的剩余寿命或已用寿命、备用空间、介质/不可纠正错误及健康告警。NVMe 同时读取 `percentage_used`、`available_spare` 及其阈值、`critical_warning`、`media_errors`；SATA/SAS SSD 按型号解释厂商磨损字段。 |
| 所有类型 | 检查当前温度，要求 **不高于 50°C**：`> 50°C` 标为超温，`= 50°C` 达标但处于上限。有多个有效当前温度传感器时列出读数，并按最高值检查；历史最高温单独说明。 |

SSD 报告必须区分“剩余寿命”和“已用寿命”，保留原始字段及含义；`percentage_used=0` 是设备报告的估计值，不代表从未磨损。厂商字段未经确认时不换算成通用健康百分比，也不自行添加健康度告警阈值。HDD 05/G 表单次非零不等于正在持续恶化。

某项必查指标未返回、设备不支持或无法读取时，按“能力缺口与回退”补查；仍缺失则写“未取得/无法判定”，不能按 0 或健康处理。

### 每块磁盘的定性结论（必填）

每块磁盘必须给出独立的 **磁盘状态**，取值仅为 **不可用 / 警告 / 健康**，并附一句证据摘要。按以下顺序判断，命中较严重状态后不被其他正常指标覆盖：

| 磁盘状态 | 判定条件 |
| --- | --- |
| 不可用 | 已有证据确认磁盘离线、失联或故障，无法正常提供磁盘 I/O。仅 SMART 查询失败、缺权限或缺少指标不构成磁盘不可用的证据。 |
| 警告 | 磁盘仍可用，但 SMART 总体失败、出现设备健康告警、当前最高温度 > 50°C、HDD 05 或 SAS G 表非零、SSD 存在介质/不可纠正错误、备用空间低于设备阈值或达到厂商寿命告警条件；必查健康指标补查后仍缺失或含义未确认时，也归为警告，注明“信息不足，无法判定健康”。 |
| 健康 | 所属类型的必查健康指标均已取得并能解释，未命中上述不可用或警告条件，且当前最高温度 ≤ 50°C。结论限于本次检查取得的证据。 |

累计 CRC、错误日志、不安全关机次数非零且尚未解释时，标为“警告（历史记录待核实）”，不能据此宣称当前故障；若证实属于历史事件且无当前异常，可判健康并保留历史说明。未经确认的 SSD 磨损字段不换算百分比，也不能用 SMART 总体通过代替寿命检查。单盘 Basic 无冗余本身不改变物理磁盘状态。

## 存储空间：容量与 RAID 状态

逐个存储空间/卷单独报告容量，远程挂载与本地空间分开，系统分区也单独列出。使用实际总容量与剩余可用字节数计算：

- 剩余比例 = 剩余可用容量 ÷ 总容量 × 100%，要求 **不低于 3%**。
- 剩余绝对容量要求 **不少于 3GB（3,000,000,000 字节）**；显示 GiB 时换算后判断，不混淆 GB/GiB。
- 两项必须同时达标；任一低于阈值时按下文容量状态规则给出结论，并指出不达标项。恰好 3% 或 3GB 对应项达标；用未四舍五入的原始值比较，不能因显示取整将不足判为达标。总量无效或可用量缺失时标为无法判定。

对 RAID 另查阵列状态、预期/实际成员及缺失/故障成员，明确**是否降级、是否正在重建/恢复/同步**。正在重建时报告进度；接口提供速度、预计剩余时间时一并报告，未提供则注明未知。区分重建、校验与空闲状态，不能将“正在重建”表述为“已恢复正常”，也不能仅因卷仍可挂载就判断阵列健康。

### 每个空间的定性结论（必填）

每个空间/卷必须给出独立的 **容量状态**，取值仅为 **不可用 / 警告 / 充足**，并说明原因。按以下顺序判断，使用未四舍五入的原始容量：

| 容量状态 | 判定条件 |
| --- | --- |
| 不可用 | 已确认空间离线、挂载失败或不可访问；或者有效容量数据表明剩余可用字节数为 0（容量耗尽，无法继续分配空间，不代表已有数据不可读取）。 |
| 警告 | 空间仍可访问且剩余量 > 0，但剩余比例 < 3% 或剩余量 < 3,000,000,000 字节；或者补查后容量数据仍缺失、无效或口径无法确认，注明“容量信息不足，无法判定”。仅接口查询失败不证明空间不可用。 |
| 充足 | 空间可访问，容量数据有效，剩余比例 ≥ 3% 且剩余量 ≥ 3,000,000,000 字节，两项同时满足。 |

容量状态只描述空间可访问性及容量，不替代 RAID 和文件系统结论：例如降级但可访问且容量达标的卷应报告“容量状态：充足；RAID：降级”。系统分区、远程挂载也逐项给出容量状态；固定用途的小分区（如 EFI）按同一阈值判定，并说明用途与总量，不能省略标签或自行豁免。

### 报告格式

报告分别包含“磁盘”和“存储空间”两部分。磁盘表每行必含：设备名、型号、序列号、类型、所属空间、**磁盘状态**、健康关键值、当前温度及判定依据。空间表每行必含：空间/挂载点、磁盘映射、总量、剩余容量、剩余占比、**容量状态**、两项容量阈值结论，以及适用的 RAID 降级/重建状态。使用逐项文字报告时，同样保留这两个状态字段，不能只给整机结论或用“SMART 通过”“容量达标”替代标签。

单盘 Basic 明确无冗余，RAID 项标为不适用，不强套多盘 RAID 判断。

## 分析与操作边界

- 分开说明物理盘健康、阵列冗余、文件系统状态、容量和 I/O。SMART 总体正常不能证明文件系统无错；单盘 Basic 即使底层显示 raid1，也不提供第二块盘的镜像冗余。
- 结合原始值、单位、型号和厂商定义解释 SMART。累计 CRC、错误日志、不安全关机次数不能单凭一次快照判断当前故障；厂商磨损字段和出厂坏块不能套用通用百分比或新增坏块解释。趋势结论需有可比的历史样本。
- 报告检查时间、磁盘与卷的映射、关键异常、证据限制及下一步。容量保留接口原单位或标明 GB/GiB、TB/TiB；远程挂载与本地磁盘分开。
- 查询健康默认只读。自检、scrub、修复、基准写入、TRIM、格式化、建池/删池、扩容和缓存配置均不从“分析状态”推导授权。用户明确要求管理操作时，核对目标盘序列号、空间归属、当前状态及授权范围，按真实接口执行并回查。
